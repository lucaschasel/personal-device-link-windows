# 桌面使用说明（0.15.1）

两台受支持设备之间的连接不绑定操作系统或控制方向。局域网支持 Windows ↔ Windows、macOS ↔ macOS、Windows ↔ macOS。两端建议安装同一版本；协议仍为 7，可与 0.13.0、0.14.0 互通，更早协议不兼容。

## 安装

Windows 完整解压应用包，运行 `Personal Device Link.exe`；保留随附 DLL 和 `bluetooth_bridge.exe`。需要 WebView2 Runtime。当前本地 Windows 包未签名。

macOS 使用与芯片架构匹配的应用 DMG，将 `.app` 拖到“应用程序”。应用包由维护者通过 GitHub 工作流构建；尚未发布时可从源码构建一次。不要把源码里的 `.command` 当作公共安装入口。安全检查与安装方法见 [Mac 安装说明](macos-quickstart.md)。

## 设备连接

两台设备接入同一局域网（Wi-Fi、有线网络或可用热点），打开应用后自动发现。点击对方设备的“连接”。无法发现时可输入对方 IP；无端口的 IPv4 地址默认使用 45832。设备出现表示能看到广播，“已连接”才表示通信握手成功。

连接不会自动控制键鼠或读取剪贴板。接收服务随应用启动；旧 CLI 若占用端口请先退出。允许系统必要的本地网络提示，检查防火墙针对本应用的访问规则，无需关闭防火墙。

## 键鼠控制

发起方在当前连接里勾选键盘、鼠标等所需功能，点击“开始所选控制”。接收方弹窗显示设备、系统、连接方式及请求内容。同意后无需控制码，拒绝或 60 秒超时不会授权。设备名称和系统由对方提供，请核对真实发起设备。

松开鼠标按钮和修饰键，等待约 3 秒开始。只接管本次选中的输入。两端均可发起或接收，切换方向前先停止当前控制。

控制中调整选项并点击“应用选择”：新增功能或改变快捷键适配需再次确认；减少功能不需要。两项都关闭可暂停键鼠。等待、停止和断开期间会释放远端输入；网络中断后恢复本地输入。

| 本机系统 | 紧急停止 | 临时操作本机鼠标 |
| --- | --- | --- |
| Windows | Ctrl + Alt + Esc | 按住 Ctrl + Alt |
| macOS | Control + Option + Esc | 按住 Control + Option |

任何页面的顶部均可停止当前控制或撤回等待中的请求。接收方也可关闭控制接收，文件传输不依赖这个开关。macOS 发起及接收控制可能需要辅助功能权限，排查见 [Mac 安装说明](macos-quickstart.md)。

跨系统快捷键适配开启时，macOS → Windows 的 Command 对应 Ctrl，Windows → macOS 的 Ctrl 对应 Command、Win 对应 Control；同系统保持原有语义。关闭后按实体修饰键对应。触摸板轻点与双指右键取决于本机系统设置。

## 剪贴板与文件

剪贴板是连接后的可选项：勾选共享，接收端同意后双向同步新复制的文字、图片和普通文件。旧内容不自动发送，可点击“同步当前内容”。任一端可关闭；重新共享需要再次同意。授权后的敏感内容也会同步。

文件剪贴板单次最多 16 个普通文件、总量 256 MiB，文件夹先压缩。文字最大 1 MiB，图片像素数据最大 64 MiB。不传播剪切删除动作。文件传完并校验后到另一端粘贴，粘贴前不要清理缓存。

独立发送文件时，在“文件传输”页选择文件，对方确认并选择新的保存位置。请求两分钟过期。可查看进度、取消及筛选传输记录；完成时 SHA-256 校验，不覆盖已有文件。任一端都可以连接对方后主动发送文件，无需开启键鼠控制。

## 没有局域网时

两端不论 Windows 或 macOS 均可选择等待或主动连接，同系统也使用相同步骤。首次先在两端系统设置配对；一端选择“等待对方连接”并点击“等待蓝牙连接”，另一端选择“主动连接对方”，填写等待端显示的蓝牙地址与频道，点击建立。就绪后任一端点击“连接蓝牙设备”，即可按上述流程双向协作。停止蓝牙会中断相关连接和传输。

两端不要同时等待或同时主动连接，切换角色前先停止蓝牙。连接或应用握手超时约 30 秒后提示重试，单纯等待对方加入不会超时。0.15.1 新增的同系统组合及 Windows 主动连接 Mac 仍需实机验收。应用层通道尚未加密，所有模式均仅用于可信设备与网络。

## 开发验证

Windows 构建：`powershell -File scripts/Build-Desktop.ps1`。Mac 构建：`bash scripts/build-macos-gui.sh`。平台对应的原生构建与实机交互需分别验证，Windows 上对 Mac Rust 接口的检查不能代替 Mac 原生构建。
