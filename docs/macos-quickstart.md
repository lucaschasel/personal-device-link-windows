# macOS 安装与安全提示

## 普通用户：安装应用包

从项目维护者的 GitHub Release 下载与你的 Mac 芯片匹配的 DMG：Apple Silicon（M 系列）选 `arm64`，Intel 选 `x86_64`。打开后把 **Personal Device Link.app** 拖到“应用程序”，之后从那里打开即可。无需每次编译，也无需双击源码中的运行脚本。

当前已提供自动生成 DMG 的工作流配置，实际下载须等维护者运行构建并发布。文件名含 `signed` 的产物仅在 Developer ID 签名、Apple 公证及票据装订检查全部成功后上传；`test` 只是临时签名测试包，可能被系统拦截。

## `.command` 被系统阻止怎么办

此前源码包中的“启动 Personal Device Link.command”是本机开发辅助入口。下载文件可能携带隔离属性，脚本无法在启动之前解除系统对自己的拦截。增加可执行权限也不能代替开发者签名和公证，因此不再把它作为普通用户的安装方式。

如果明确提示“无法验证开发者”或“Apple 无法检查是否包含恶意软件”，先确认下载来源和文件完整性。对于你确认可信的未公证测试包，可以按 Apple 官方步骤，在尝试打开后进入“系统设置 → 隐私与安全性”，在系统提供该选项时选择“仍要打开”。这只适用于明确知情的单个应用许可；不需要关闭 Gatekeeper 或全局删除隔离属性。

如果显示“将损坏电脑”“已损坏”或系统策略禁止打开，先停止尝试，记录完整提示，重新下载并核对维护者提供的 SHA-256。不要把不同原因一律当成可忽略的警告。详见 [Apple：安全打开 Mac 上的 App](https://support.apple.com/102445)。

正式向其他人分发时，维护者应提供 Developer ID 签名且通过 Apple 公证的应用。临时签名、改名、ZIP 包或脚本本身都不能承诺消除这类拦截；参考 [Apple 公证要求](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution) 和 [发布指南](releasing.md)。

## 已有源码：只需构建一次

如果暂时没有已发布的应用包，在安装 Rust stable、Node.js LTS、Xcode Command Line Tools 后，在终端进入你已检查并信任的源码目录，执行：

```bash
bash scripts/build-macos-gui.sh
open "desktop/src-tauri/target/release/bundle/macos/Personal Device Link.app"
```

这会编译应用并把两项蓝牙组件一同装入 `.app`。将生成的应用拖到“应用程序”，以后直接打开它，不必每次编译。更新源码版本后才需要重新构建。此方式生成本机测试应用，不等于正式签名或公证。运行脚本发生编译错误时请保留完整输出。

根目录 `.command` 仅保留为开发便利入口，也可能被系统拦截，不是安全问题的解决方案。

## 辅助功能与本地网络权限

首次发现设备时按系统提示允许本地网络访问。发起或接收键鼠控制时，按提示为当前应用授予辅助功能权限。蓝牙连接还可能需要蓝牙权限。安装安全检查与这些功能权限互相独立。

如果旧版本已授权，新版本仍提示权限不足：退出所有应用副本；在“应用程序”中选定要使用的那一份；进入“隐私与安全性 → 辅助功能”，移除失效的旧条目，再添加当前 `.app` 并启用；重新打开同一份应用。本地重编译或签名变更可能使旧授权失效。

## 与另一台设备协作

对方可以是任一台受支持的 Windows 或 macOS 电脑，包括另一台 Mac。局域网连接后，任一端可发起控制、发送文件或请求剪贴板共享，接收方弹窗确认。Mac 并非固定的控制端或接收端。

蓝牙桥接也已实现同系统与跨系统的双角色连接。两端均可选择等待或主动连接；一端等待、另一端填写地址与频道。链路建立后应用功能双向可用。macOS 新增监听实现仍需原生构建与实机验收。完整流程见 [桌面说明](desktop.md)。
